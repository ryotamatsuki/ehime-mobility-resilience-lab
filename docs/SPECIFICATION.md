## 1. プロダクト名称

正式仮称：

**Ehime Mobility Resilience Lab**

タグライン：

**「もし、ここが通れなくなったら。」**

説明文：

災害が起きたときに見るアプリではなく、災害が起きる前に「交通が止まった愛媛」を何度も試すためのシミュレーション基盤。

---

## 2. プロダクト目的

本プロダクトの目的は、

公共交通・道路・物流を構成する交通ネットワークの一部が利用不能または性能低下した場合に、愛媛県内の人・車・物の移動へどのような影響が生じるかを、平時に定量的に検証できるようにすること

である。

特に以下の政策判断を支援する。

1. 公共交通停止時に、どの地域・人口の移動可能性が低下するか
2. 道路寸断時に、自動車交通がどこへ迂回するか
3. 迂回交通により、どこに新たな混雑が発生するか
4. 貨物交通・物流拠点へのアクセスがどの程度低下するか
5. 救援物資をどこまで輸送できるか
6. どの道路・交通機能を優先的に維持・復旧することが効果的か
7. 現在の交通ネットワークにどのようなSingle Point of Failureが存在するか

本プロダクトは災害発生を予測するシステムではない。

交通ネットワーク障害に対するStress Testを行うシステムとする。

## 3. 基本設計原則

### 3.1 Phase A単独完成原則

Phase Aだけで、コンペ応募及び行政PoCとして成立する完成品とする。

Phase Bが実装されなければプロダクトが成立しない設計は禁止する。

### 3.2 Phase B疎結合原則

愛媛県新地震被害想定GISは、Phase Aのコア計算機能から完全に分離する。

Phase Bは、許諾等の条件を満たした場合に追加するHazard Adapterとする。

### 3.3 Stress Test原則

「この道路が災害時に確実に壊れる」と予測・断定しない。

「この道路が使用不能になった場合、交通ネットワークに何が起きるか」を分析する。

### 3.4 Data Transparency原則

すべての分析値を以下に分類する。

* 公式観測値
* 公式統計からの加工値
* モデル推計値
* ユーザー設定値

表示上も区別する。

### 3.5 Reproducibility原則

すべての分析について、

* 使用データ
* データバージョン
* モデルバージョン
* シナリオ
* パラメータ
* 実行日時

を追跡可能にする。

### 3.6 Non-engineer Operation原則

コーディング知識のない自治体職員が日常運用できることを必須要件とする。

### 3.7 Open / Portable原則

可能な限り、

* オープンデータ
* OSS
* 標準ファイル形式

を使用し、有料API・特定クラウド・特定LLMへの依存を避ける。

## 5. 分析対象地域

最終成果物は愛媛県全域を対象とする。

モデル精度検証については、データの豊富な松山都市圏を重点検証地域とする。

空間粒度は原則として、

* 愛媛県全域：1km程度
* 松山都市圏・重点地域：500m程度

とする。

観測データの粒度以上に見かけ上の精度を高めることは避ける。

## 6. Phase構成

### 6.1 Phase A：Open Mobility Stress Test

Phase Aは本プロダクトの正式なコアプロダクトとする。

愛媛県新地震被害想定GISを利用しなくても全機能が成立すること。

道路

* 完全通行止め
* 容量低下
* 速度低下
* 車種制限

鉄道

* 路線停止
* 区間停止

バス

* 路線停止
* 区間影響

港湾・航路

* 港湾利用不能
* 航路停止

複数障害を同時に設定可能とする。

### 6.2 Phase B：Official Hazard Scenario Adapter

Phase Bでは、愛媛県新地震被害想定GIS等を利用して、ハザード情報から交通ネットワーク障害条件を生成する。

ただしRelease Gateを満たした場合のみ実装・公開する。

#### Gate B-1

GIS利用条件について必要な確認・許諾が取得されていること。

#### Gate B-2

以下の利用可否が明確であること。

* 座標変換
* clipping
* raster/vector変換
* Spatial Join
* Intersection
* 派生数値
* Web表示
* スクリーンショット
* GitHub公開
* 原GISを含まない加工結果公開

#### Gate B-3

許諾内容をリポジトリ内に記録する。

#### Gate B-4

許諾が得られなければPhase Bは実装しない。

Phase Aのみで完成版とする。

## 14. Synthetic OD仕様

### 14.1 基本思想

ゼロからGravity Modelだけで生成しない。

公開されている実績統計を最大限制約条件として用いる。

### 14.2 通勤・通学OD

市町間流動は国勢調査等の実績値を利用する。

市町間総量は原則維持する。

市町内部細粒度のみ推計する。

### 14.3 空間分解

発生側：

* 人口
* 年齢
* 就業人口
* 世帯

集中側：

* 従業者
* 事業所
* 学校
* 商業
* 医療

### 14.4 非通勤目的

買物・通院・私用等はGravity Model等で推計する。

### 14.5 県外流動

公開都道府県間ODを外部制約として用いる。

### 14.6 貨物OD

乗用車とは別モデル。

大型車交通量等を用いて校正する。

## 41. 最終的なプロダクト価値

本プロダクトは、

「災害ハザードを表示する地図」

でも、

「公共交通を可視化する地図」

でもない。

目指すものは、

公共交通・道路・物流のネットワークを意図的に壊し、地域社会への影響を測定し、どの交通機能を守るべきかを平時に検証するMobility Resilience Digital Twin

である。

最終的な問いは、

「もし、ここが通れなくなったら、愛媛の人と物の移動はどう変わるのか。」

とする。

## 42. Decision Lock

以下については、新たな明確な根拠がない限り変更しない。

1. 公共交通レジリエンスが中心。
2. 防災は主要ユースケース。
3. Phase Aだけで完成。
4. Phase Bは許諾後のみ。
5. 新地震被害想定GISへ依存しない。
6. LLMをコアにしない。
7. 公共交通・自動車・物流を統合。
8. 民間在庫サプライチェーンは対象外。
9. Synthetic ODは推計と明示。
10. 公式値・加工値・モデル値・仮定を区別。
11. 非エンジニア運用必須。
12. データ更新・版管理・再現性を後付けにしない。
13. GitHub Pagesを公開基本とする。
14. 高負荷計算はPython分析レイヤー。
15. コンペだけでなく行政継続利用を完成条件とする。
